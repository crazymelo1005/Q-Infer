## 2. 从预览版读出的七条趋势

| # | 趋势 | 证据 | 对引擎的含义 |
|---|------|------|-------------|
| 1 | 混合注意力成为默认 | 3/4 层 Gated DeltaNet + 1/4 层稀疏注意力（QSA） | KV 从「单一张量」变成「循环状态 + 稀疏 KV」两类，必须分开配额与量化 |
| 2 | 索引/元数据也开始量化 | vLLM 为 QSA 单开 `indexer_kv_dtype` | 量化从「权重/KV 两轴」扩到「三轴+」；引擎要有可插拔的精度旋钮 |
| 3 | 外挂记忆表进入模型本体 | 51B N-gram 嵌入表，访问确定、可预取 | 主机内存成为模型的一部分；引擎的调度中心从 device 扩到 host↔device |
| 4 | 超稀疏 MoE 加剧 | 125B 总参 / 6B 激活（4.8%），24,576 专家 | 权重永远大于显存；专家缓存/卸载从「优化」变成「必需」 |
| 5 | 多 token 预测内置 | 自带 4B MTP 头 | 投机解码从「外挂技巧」变成基线能力；引擎必须一次前向验证多 token |
| 6 | 成本效率导向 | 训练成本约为前代 1/9；目标「Ultimate Cost-Efficiency」 | 同预算下模型更大 → 容量压力只会继续增长 |
| 7 | 多模态原生 | 文本/图像/视频 + vision encoder | 视觉编码器驻留与图像特征缓存成为引擎的常规模块 |

### 2.1 趋势 3：外挂记忆表进入模型本体

模型设计里 n-gram 表被放在第 2 层，目的是让主存预取与第 1 层计算并行重叠——即「串行→并行」是模型作者写进架构的意图。

但当前引擎（Strata）只是把它丢给 OS page cache，没有专用预取器。这意味着：

模型架构已经为确定性预取留出了提前量，而当前引擎没有利用。

但这不再是空白：vLLM 官方 recipe（`VLLM_PLE_CPU_OFFLOAD`）与 Qwen 官方 README 已用「异步卸载到主机内存并与计算重叠」实现同类能力（[官方]，见 [05-engine-landscape.md](05-engine-landscape.md) §7.2）——该机制可作为切入点，但不构成独占机会。

### 2.2 趋势 4 与 7：容量问题不会消失

Qwen4.5 / Qwen5 的公开目标是 5–10 万亿参数。即使激活率继续下降，总权重与总显存之间的鸿沟只会扩大。因此：

本设计的第一性假设是权重永远装不进显存，而不是先装进去再优化。

这与 vLLM/SGLang 的假设恰好相反——它们的全部调度技巧都建立在「权重常驻」之上。

## 3. 对引擎设计的约束

1. 存储层级必须是一等公民：显存 / 主机内存 / SSD 三层，且每层要有显式的数据流与预取调度，不能交给 OS 碰运气。
2. 两套 KV 配额：GDN 状态按并发分配、QSA KV 按上下文×并发分配，独立管理。
3. 专家检索要有预测：路由是 top-10/512（约 2%），专家共现有结构可利用（热专家聚类、会话亲和）。
4. 投机解码是基线：MTP 头已在模型里，引擎不实现就等于白送 1.6–3× 的收益。
5. 精度旋钮可插拔：权重/KV/索引器三处独立，且要支持 FP8 → 4-bit → 3-bit（TurboQuant 类）的渐进路线。
6. 主机侧算力要能用满：AVX2 环境下 CPU 是本机第二算力，未命中专家必须能与 GPU 并行就地计算。
