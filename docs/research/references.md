`raw[0]` 指的是序列的第 0 个 cell，不是尾巴缓冲的第 0 格；两处注释本来就一致。块键的旋转位置是 `pos_base + R * b`（块 b 的首个 cell 的位置，`block_pos` 记的就是它），池化的均值写成 `fma(0.25, sum, 0)`（R = 4 的 1/R），归一之后再逐维乘 `w_k_norm`（`values[d] = scale * mean * gamma[d]`）。至此 `indexer_key_append` 的实现没有需要猜的地方了。 本仓库实现 `src/dense/qsa_indexer`：与独立参考（角度现算、不查表）一致（块 0 相对 L1 8.1e-08、块 1 为 0），备用槽等于序列 cell 0 的键、`dead` 与之一致；三处错读法各按错的算一遍：旋转取块末 cell 1.38、忽略 pos_base 0.34、块边界错位一格 0.61；4 处变异全杀（含「备用槽用当前块键而不是 dead」）。一处夹具教训（与层分派那片同族）：早先每个 token 现调一次带固定种子的随机函数，于是 8 帧完全相同，「块边界错位」那条对手被相同数据抹平（偏离 0）；改成一次生成 8 个不同的 cell 之后它才起作用。 另：该 artifact 的 QSA 有两个逐头归一 `attn_q_norm` / `attn_k_norm`（各 [256] F32 = head_dim，在 rope 之前按头做），与索引器池化、收尾的 o 归一用的是同一种算术（分母 `sqrt(mean(x²) + eps)`、eps 加在均值上、先归一后乘 gamma）。注意这与 GDN 的 l2 归一口径相反（那边 eps 是加在平方和上的绝对下限，见 [S-56]），两处不可混。本仓库把这一份抽到 `dense/norm.hpp`（`rms_norm_rows`），索引器键那一处已改用它，免得三处各写一遍口径；两处错的读法各按错的算一遍（eps 加在平方和上 0.82、先乘 gamma 再归一 0.019），3 处变异全杀。 本仓库实现 `src/dense/qsa_indexer` 的 `qsa_indexer_prep`（`indexer.q_proj` 的输出按头归一 + rope 得 q_idx；键则**原样**存进尾巴）：与独立参考一致；并把「键是原样的」钉住——拿「先逐个归一」的键去池化，池化键与用原始键不同（norm∘mean ≠ mean∘norm），这条把那条看似合理的错读法挡在外面；2 处变异全杀（q_idx 不做 rope、只归一一行）。
