# 候选方向

本文收录架构层面尚未验证的候选方向。这些是候选，不是规格；不得作为立项理由引用。

判据：一条候选只有在"上游架构上做不了"而非"上游没做"时，才具备结构性价值。否则它只是工程深度，随时可被上游补齐。

存疑等级：检索级表示未找到公开对应实现，属检索结论而非穷尽证明。

## P-01 三类流量统一步预算

把每一步的 PCIe 搬运抽象为带截止时间的装箱问题：给定本步字节预算、三类流量的预测需求，以及"每步只有一次 GPU 与 CPU 汇合"这一硬时限，求准入与优先级的联合分配。

机制要点：

1. 步开始前收集三类预测：表行由上一 token 确定性算出，专家由共现与会话亲和给出概率，KV 由上下文位置与块粒度给出。
2. 以字节预算与消费点时刻为约束，按收益除以字节排序做贪心准入。并发规模小，贪心足够。
3. 正确性所需的搬运保留保底额度；预测性搬运用剩余额度，额度不足时主动放弃并记账，而不是临到消费点阻塞。
4. 所有搬运与计算共用一个汇合点；未在汇合前就绪的预取直接丢弃并计入迟到数，不为它增加同步。
5. 预取按引用计数与世代号锁定到消费完成，避免中途被驱逐。

成本与风险：放弃策略若错会放大长尾；收益依赖三类预测各自成立；必须落盘每步的预算分配、实际用量与迟到数，否则无法调参。

测量：指标为步延迟 P99、PCIe 实际利用率、预取迟到率、同机同档 decode 吞吐；对照为三类独立按比例分配；必须在内存紧张与充足两种条件下分别测。

## P-02 精度作为缓存维度

把比特宽度变成缓存的第三个维度：缓存条目是"块、驻留层、比特宽度"三元组，淘汰时同时决定踢谁与降谁的精度。

机制要点：

1. 混合精度缓存的总字节仍在内存预算内。
2. 分层精度：显存热区高比特，主机 pinned 区中比特，NVMe 冷区保持压缩态。
3. 淘汰顺序为先降比特、再降层、最后丢弃。把即将淘汰的热块降比特，通常比搬到主机内存更划算。
4. 主 KV 与索引器 KV 本就该用不同精度，这是已有的第二个维度，可推广到专家与表行。

成本与风险：这是四个方向中唯一直接触碰输出分布的，必须有困惑度、任务集与长文三重回归。混合精度意味着反量化发生在缓存路径上，须融进内核，否则省下的带宽被换算吃掉。每种块型都要支持同块多精度，工程量不小。

## P-03 投机感知预取

投机在验证之前已经生成草稿树，这棵树本身就是对未来的概率预测。把预取对象从"上一个已提交 token 的确定性索引"改为"草稿树的并集，按接受概率加权"。

机制要点：

1. 表行索引按草稿树每条路径算出后取并集，做一轮预取；专家同理。
2. 接受率低时收缩预取深度，否则每次拒绝都造成白搬。
3. 草稿被接受时其预取直接命中；被拒时保留结果供下一轮使用。
4. 树的预取放大系数作为 P-01 的输入之一。

成本与风险：不做接受率门控时，预取 IO 随草稿长度线性放大，可能把收益吃光。投机子系统需向调度器暴露草稿树与历史接受率，接口设计要防止两个子系统互相拖慢。

## P-04 CPU 与核显共享总线联合调度

核显与 CPU 共享同一条内存总线，因此核显多跑一点，CPU 就少一点。把两者显式建模为同一条总线上的两个工人，按每个专家组的计算强度与带宽强度互补分配，并共同受总线带宽约束。

机制要点：

1. 对未命中专家组估计字节与浮点运算之比：带宽密集的给 CPU，计算密集的给核显。
2. 用同一个总线预算约束两者合计访存。
3. 命中率越高，走这条路的字节越少，核显价值越小。两者此消彼长，必须与 P-01 的预算一起算。
4. NPU 不参与专家计算。

成本与风险：若 G-07 判定为带宽瓶颈，本方向直接作废。接口与驱动的成熟度、以及核显与 CPU 的数据一致性开销都需要评估。

## 与实现方式决策的关系

本文讨论框架内还能往哪创新，不改变立项判定。

- 若 P-01 拿不出源码级证据证明上游架构上做不了，则应优先给上游提交改动，而不是新写引擎。
- 四个方向都应先完成目标基线实测与门禁测量，这些产出与是否自行实现无关。
- 任何方向的收益主张，分母都必须是本机实测。
