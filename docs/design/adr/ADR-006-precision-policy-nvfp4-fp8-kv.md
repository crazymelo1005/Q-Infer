# ADR-006：精度策略 —— NVFP4 权重 + FP8 KV + 索引器 KV 独立精度档

**状态**：Accepted
**日期**：2026-10-09

---

## 背景

「量化」不是单一开关，而是四个独立轴（研究 04 §1）：对象（权重/激活/KV/累加）、时机（QAT/PTQ）、数值表示（INT/FP/码本/三值）、粒度（per-tensor…per-16）。Flash-Next 对推理有两处特殊：

1. 它有两种 KV：36 层 GDN 循环状态（随并发数增长）+ 12 层 QSA KV 与它的索引器 KV（随上下文×并发增长）。
2. 它的 n-gram 表与专家权重是两个独立的体积大头（51B / 125B）。

vLLM 的官方 recipe 已证实：索引器的 KV 也需要单独量化（`--attention-config.indexer_kv_dtype fp8`）——它与主 KV 的敏感度、体积都不同。

## 决策

采用三（+1）处独立旋钮的精度策略：

| 旋钮 | 默认 | 备选 | 依据 |
|------|------|------|------|
| 权重 | NVFP4（Blackwell 第五代 Tensor Core 原生加速） | IQ2_XS / IQ3_XXS（GGUF 生态）、IQ4_XS、三值 | 环境2 sm_120 对 NVFP4 有硬件路径 → 优先；GGUF 档兼容 llama.cpp 生态复用 |
| KV（QSA 主 KV） | FP8 | 4-bit（SAW-INT4 类，兼容 paged 布局）；3-bit（TurboQuant 类）仅实验档 | 反量化必须融进 attention 核，否则把省下的带宽又读回来 |
| 索引器 KV | FP8（独立旋钮） | 4-bit | 对质量更敏感、体积更小 → 可单独调 |
| 累加精度 C | FP32（稳定） | BF16（更快） | 由自动标定决定 |

## 备选方案

1. 单一精度档（权重+KV 一套） —— 否决：混淆「权重轴」与「KV 轴」会同时错判显存占用与速度上限（研究 04 §2）。
2. 全部 FP8 —— 部分否决：体积太大装不下；且环境2 native NVFP4 硬件路径被浪费。
3. 激进统一降到 3-bit 权重 + 3-bit KV —— 否决为默认：质量未达标前不进默认档。
4. 分轴独立旋钮 —— 采纳。

## 后果

正面
- 体积/质量折中可逐轴调优，不互相绑死。
- 索引器 KV 单独降档 → 长上下文下省显存而不显著伤质量。
- NVFP4 走硬件路径 → 相比 GGUF 软件解码头，同精度更快。

负面
- 每轴都要有误差上界与评测（perplexity + SWE-bench 类任务集 + LongBench 长文）。
- 3-bit KV（TurboQuant 类）没有独立复现，且其残差在 1-bit 下方差偏高，对 top-1/贪婪采样不友好 → 必须专用评测（区分「无偏」与「贪心友好」），只作实验档。
- 多档位增加测试矩阵。（缓解：只对默认档 + 一个激进档做完整评测。）

## 质量门禁

- 投机解码：只验证、不改分布（草稿被拒则回退，数学上输出分布不变）。
- 量化：每个非默认档必须有评测报告，未达标不得进默认档。
- 评测口径：投机/量化收益必须用真实任务集（SPEED-Bench 类），禁用随机 prompt。
