# ADR-003：n-gram 记忆表采用显式索引预计算与双缓冲预取，而非依赖操作系统页缓存

**状态**：Accepted（条件性：依赖 G-04 / G-10 / G-13）
**日期**：2026-10-09

---

## 背景

Qwen3.8-Flash-Next 带一张 51B 的 n-gram 记忆表（FP8 约 51 GB，4-bit 约 28.8 GB），远超显存。模型作者把它放在第 2 层，是因为第 t 步要查的行由第 t-1 步已生成的 token 决定，行索引可以提前一步算出。这是模型自带的串行转并行设计。

现状：上游引擎把它放在 SSD，每 token 经操作系统页缓存读若干小行，没有专用预取器（[research/01-strata-engine.md](../../research/01-strata-engine.md) §3）。模型把提前量交给了引擎，引擎没有使用。

## 决策

为记忆表建立显式预取子系统：

1. 索引预计算。第 t-1 步的 token 一确定，立即计算第 t 步要读的表行索引，纯确定性，无需等待计算。
2. 双缓冲。缓冲区 A 服务第 t 步，缓冲区 B 在第 t 步的显存计算期间被异步填充。
3. 三级分级。高频行常驻显存，中频行放主机 pinned 区，长尾行留在 NVMe 并直接映射。
4. 批量聚合。同步内所有序列的所有查表请求合并为尽量少的连续大块读。
5. 缺行必须阻塞等待。表行是精确输入，不允许取旧值或跳过的有界近似，因此预取必须至少提前一步完成。

预填期的路径另见 [engine.md](../engine.md) §4。

## 备选方案

1. 交给操作系统页缓存（上游现状）。否决为主路径：浪费了模型给出的提前量，冷启动首请求实测仅约稳态的 1/18。
2. 全表常驻主机内存。否决：4-bit 档 28.8 GB 即吃掉 64 GB 机器近一半内存，挤压专家常驻区。
3. 按需同步读，不预取。否决：把 SSD 放进每步解码的关键路径。
4. 显式预取加双缓冲加三级分级。采纳。

## 后果

正面：

- 把记忆表 IO 从解码关键路径移出，消除每步的表未命中串行等待。
- 改善冷启动曲线，对应实施顺序第 6 项的验收指标。

负面：

- 成立与否取决于行访问的局部性（G-04）。长尾行若散布随机，预取命中率低、收益不成立。
- 增加一个独立的预取调度器，以及双缓冲带来的显存与内存开销。

## 与上游的关系

表行的异步预取并非独有：上游推理引擎的 n-gram 表卸载路径已实现该机制（S-01、S-25），上游引擎亦已实现专家侧的跨层预测预取与批量 IO（S-02）。

因此本决策不构成「无人做过」的差异点。其成立依据是「相对上游已实现的专家侧预取，表行侧的确定性预取是否值得单独一套机制」，并受 G-04、G-10、G-13 三重门禁约束。其中 G-10 必须在主机内存余量紧张与充足两种条件下分别测：上游同方向机制在余量紧张时为负收益（实测 −32.6%），在余量充足时为正收益（+25.7%）。

## 门禁

本 ADR 为条件性接受。

- G-04 通过：保留该子系统，进入实施顺序第 6 项（见 [engine.md](../engine.md) §17）。
- G-04 不通过：砍掉该子系统，退守 [engine.md](../engine.md) §5 的专家缓存，并把负结果写入 [risks.md](../risks.md)。
