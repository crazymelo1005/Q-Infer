# ADR-007：记忆表访问退守按需读与有界行缓存，放弃提前一步的双缓冲预取

**状态**：Accepted。取代 [ADR-003](ADR-003-ngram-table-explicit-prefetch.md)（该决策为条件性接受，条件之一 G-04 已不通过）。
**日期**：2026-10-09

---

## 背景

[ADR-003](ADR-003-ngram-table-explicit-prefetch.md) 为记忆表建立了显式预取子系统（索引提前一步、双缓冲、三级分级、批量聚合为顺序大块读），并把成立条件挂在门禁 G-04（表行访问局部性）上。

G-04 已在环境2 上离线重放实测（方法：用参考引擎自身的 n-gram 哈希重放表行索引，哈希经其 oracle 向量逐位校验；语料为参考引擎仓库自身的文档与源码，4K 至 262K token；见 [`../../research/02-qwen3.8-flash-next.md`](../../research/02-qwen3.8-flash-next.md) §3.2 与 [`gates.md`](../gates.md) 的 G-04 行）。结论是去重后的访问序列既无顺序性也无局部性：

- 相邻请求落在同一 4 KiB 页的比例为 0，去重后仍为 0。这不是抽样偏差，而是结构性的：16 个头把表切成 16 个互不相邻的连续区间（各自约 20,000,000 行、约 1.8 GB），一个 token 的 16 行分别落在 16 个区间里，任何相邻两次请求都必然异区间、必然异页。按页合并或顺序大块读的收益为零。
- 行级重复确实存在且随上下文增长（重复率 4K 档 0.28、32K 档 0.42、262K 档 0.59），但它是长距离复现，不是近邻复用：262K 档的复用距离中位数约 10,240 次请求（约 640 token），落在 16 次请求窗口内的重复只占 0.14%。因此「提前一步」的预取几乎命中不到重复。

G-04 的通过标准是「去重后存在可利用的顺序性或局部性」，实测两项皆无，故不通过。按 [engine.md](../engine.md) §4 与 ADR-003 的原定后果，砍掉表行预取子系统。

## 决策

1. 表行按需读取，与上游一致。一个 token 需要 16 行（每行 90 字节，共 1,440 字节），在需要时发起读，读回后参与该层的 embedding 相加。
2. 保留并启用有界行缓存，不另建预取调度器。缓存按「8 路组相联、按行号哈希定组、组内轮转替换」实现，容量默认 1,048,576 行（IQ4_NL 约 90 MB，即上游 `--ple-row-cache` 的默认值）。它吃下的是长距离复现：G-04 实测该容量在 4K / 32K / 262K 档的命中率分别为 0.28 / 0.42 / 0.58。
3. 保留「token 确定即发起读、消费点前收集」的重叠窗口。这不需要双缓冲也不需要提前量：引擎在 token 已知时即可发起 16 行的读，与 embedding 落位重叠。上游已按此工作（其自报测量为 16 次串行页读约 2.10 至 2.61 ms/token，即 0.5 MB/s，属延迟受限而非带宽受限）。
4. 取消以下 ADR-003 的机制：双缓冲、按块合并为顺序大块读、表行的三级分级迁移、预取迟到数记账中对表行的部分。

## 备选方案

1. 维持 ADR-003 的显式预取子系统。否决：G-04 不通过，其两个前提（去重后有顺序性、近邻有复用）均被实测否定。
2. 用投机的草稿树扩大提前量（原 P-03）。否决：G-04 显示重复的复用距离远大于一个草图窗口，草稿树并集只会放大 IO 而不提高命中。
3. 把整表常驻显存或主机内存。否决：4-bit 档 28.8 GB，超过显存，也吃掉主机内存近一半（见 [engine.md](../engine.md) §3.4 与 G-11）。
4. 按需读加有界行缓存。采纳。

## 后果

正面：

- 去掉一个独立预取调度器、双缓冲的显存与内存开销，以及相应的记账复杂度。
- 行缓存对长距离复现的收益保留，且与上游同构，便于对照。

负面：

- 表行读的延迟仍落在 decode 步内。上游实测 16 行串行约 2.10 至 2.61 ms/token；本设计只保留「token 已知即发起」的重叠窗口，不再承诺更多。该延迟能否藏进一个步长由 G-10 判定（判定对象改为按需读，而非预取）。
- 冷启动首块无前序可重叠，仍只能阻塞读取。

## 门禁

- G-04：不通过（实测）。本 ADR 按原定后果执行。
- G-10：仍待测。判定对象由「预取往返能否藏进一个步长」改为「按需读的往返能否被重叠窗口吸收」。
- G-13：仍待测。它现在只约束表行的 IO 次数放大（验证窗口内的草稿 token 各自要读 16 行），不再约束预取深度。
