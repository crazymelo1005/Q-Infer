# ADR-004：消费级双卡禁止每层同步的张量并行，改用按层切分 / 专家并行 / 双实例

**状态**：Accepted
**日期**：2026-10-09

---

## 背景

目标架构必须同时服务消费级单卡与消费级双卡。双卡看似「显存翻倍、算力翻倍」，但消费级平台有三条硬约束（研究 04 / 硬件文档）：

1. 第二条 PCIe 槽往往只有 x4，或挂在芯片组下：多数消费级主板是 x16+x4；少数（如 Z890 Pacific）为 x8+x8。第二张卡带宽可能只有第一张的 1/4。
2. 不支持 NVLink：跨卡通信只能走 PCIe，延迟高、带宽低。
3. 第二张卡的显存不是「更大的地址空间」：模型逻辑只有一份，多出来的显存是「更热的专家缓存」。

服务端派引擎（vLLM TP8、TEP 等）默认跨卡通信有 NVLink 级带宽。该前提在消费级双卡上不成立。

## 决策

消费级双卡禁用「每层都需要跨卡同步」的张量并行（TP），因为那会把慢 PCIe 链路放进每一层的关键路径。改用以下三种策略（按优先级）：

| 策略 | 做法 | 适用 |
|------|------|------|
| A. 按层切分（layer-split） | 48 层在两卡间粗粒度切开，各卡独立跑自己的层 + 自己的专家缓存 | 单会话、低延迟优先 |
| B. 专家并行（expert-parallel） | 两卡各持约一半专家的常驻副本；未命中的从共享主存专家池取 | 单会话、命中率优先 |
| C. 双实例数据并行 | 两卡各跑一个独立引擎实例，共享同一份主存专家池与记忆表 | 多会话、吞吐优先 |

关键配套：共享主存专家池。两张卡/两个实例不必各自复制 40–70GB 专家与 28.8GB 记忆表——主机内存是共享资源，由统一页表（[engine.md](../engine.md) §3）管理、引用计数共享。

## 备选方案

1. 张量并行（TP） —— 否决：每层一次 all-reduce 走 PCIe，慢链路进关键路径。
2. 流水线并行（PP） —— 部分否决：Flash-Next 的 n-gram 嵌入表初始不支持 PP（官方 recipe），且 PP 的层间传递同样走 PCIe。
3. 各卡独立复制全部数据（不用共享池） —— 否决：内存放不下两份 40–70GB 专家。
4. 按层切分 / 专家并行 / 双实例 + 共享主存池 —— 采纳。

## 后果

正面
- 代码与数据格式只有一套：卡数只改变 `machine profile`（[engine.md](../engine.md) §10）与分配策略，不改代码路径——「单卡能跑、加卡更好」。
- 双卡命中率约 0.70 → 0.95+（Strata 双卡合计 44GB 实测 97.7%）。
- 避免了消费级双卡最常见的「带宽被第二张卡拖垮」。

负面
- 按层切分下，两张卡负载可能不均（层间计算量不同）。
- 专家并行需要一个跨卡/跨实例的命中通知机制，比纯环境2 复杂。
- 双实例方案的会话调度需要粘滞（同一会话固定到一个实例）以保前缀缓存有效。

## 门禁（Gate）

具体选 A 还是 B 取决于 G-08（双卡时第二张卡的 PCIe 实际档位与带宽）：若第二槽为 x8 且带宽充足 → B 可行；若为 x4/芯片组 → 偏向 A（尽量少跨卡通信）。
