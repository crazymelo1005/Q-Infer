# 模块接口

本文定义模块之间的契约。实现方案见 [engine.md](engine.md)。接口只定对外行为，不定内部实现；尚未确定的部分集中列在最后一节，不在设计阶段虚构。

---

## 1. 通用约定

- 缓冲区在启动时一次性分配，运行期不分配。
- 请求分两类：必需请求与尽力请求。必需请求由消费点阻塞等待；尽力请求可被丢弃，但必须记账。
- 时间以 decode 步为粒度，所有截止时间都折算为步数。
- 每次准入、丢弃、迟到都计入观测输出。

## 2. 统一页表

所有逻辑块（专家、表行块、KV 块）都通过页表申请与归还，子系统不直接持有裸指针。

条目字段：

| 字段 | 含义 |
|------|------|
| 逻辑块 id | 专家 id、表行块 id 或 KV 块 id |
| 类别 | 专家 / 表行 / KV |
| 所在层 | VRAM / 主机 pinned / NVMe |
| 物理偏移 | 在所属层中的位置 |
| 引用计数 | 被引用次数，归零后才允许驱逐 |
| 世代号 | 防止驱逐与正在进行的预取互相踩踏 |
| 热度 | 供替换策略使用 |
| 预取状态 | 空闲 / 在途 / 就绪 |

操作：`acquire(id, deadline, must)`、`release(id)`、`advance_generation()`、`query(id)`。

不变量：

1. 预取一旦发出即锁定到消费完成，中途不得被驱逐。
2. 驱逐前引用计数必须归零。
3. 跨卡与跨实例共享的块由同一份页表管理，不重复复制。

## 3. PCIe 字节预算仲裁器

输入：本步的字节预算；若干请求，每个请求带类别、字节数、消费时刻、是否为必需。

优先级自高到低：

1. 本步必需的 KV 换入
2. 本步必需的表行
3. 预测性的专家，按收益除以字节排序

输出：每个请求返回准入或延迟；延迟计入迟到数。

约束：每步只有一个 GPU 与 CPU 汇合点；不为迟到的请求增加同步点。

## 4. 计划层到存储层

计划层每步向前输出四类需求：

| 输出 | 性质 | 消费者 |
|------|------|--------|
| 表行 id 列表 | 确定性，由上一 token 唯一决定；本设计只按需读，不做预取 | 表读取与预算仲裁器 |
| 专家 id 与概率 | 概率性，来自共现与会话亲和 | 预算仲裁器 |
| 投机草稿树 | 概率性，来自投机子系统 | 预算仲裁器 |
| 精度档 | 决策 | 执行引擎与 KV 池 |

约定：这些输出是需求而不是命令，是否满足由预算仲裁器裁决。

## 5. KV 池

两个独立池，独立配额、独立限额、独立驱逐：

| 池 | 规模随什么增长 | 备注 |
|----|---------------|------|
| GDN 循环状态池 | 并发序列数 | 与上下文长度无关 |
| QSA KV 池（含索引器 KV） | 上下文长度乘以并发 | 常驻热窗，其余分块流式读 |

操作：`reserve(pool, bytes)`、`admit(sequence)`、`evict(pool)`、`usage(pool)` 返回余量。

约束：调度器必须同时观察两个池的余量，任一不足即拒绝新序列。

## 6. 机器画像

标定阶段产出，落盘后可复用、可对比。实现与字段见 `measure/calibrate.py`，环境2 的产物见 `measure/results/*-calibrate-环境2.json`。

测得的输入：显存总量与空闲、显存带宽（device STREAM）、PCIe 档位与 H2D/D2H 有效带宽、主机内存带宽、按核心类型区分的量化内核吞吐、decode 步长分布、专家槽位与缓存字节、命中率（静态覆盖与会话内）、每生成 token 的位置数（投机放大）、表行读往返延迟。

推导出的参数：每步 PCIe 字节预算、专家槽位数、KV 满上下文与常驻窗字节、并发分池（QSA 侧每 cell 字节；GDN 侧待 SSM 几何）、起草长度上限、核显总线份额（一个 decode 步里允许核显占用的总线字节数；默认 0 即不启用，上限须实测）。

设计输入（非测得，须显式给出）：`io_share`——一个 decode 步里允许被 IO 占用的时间份额，本设计取 0.5。

消费者：预算仲裁器、专家缓存、KV 池、核显总线份额限流器（第 8 节）。

## 7. 观测输出

每步至少记录：命中率、PCIe 实际用量、预取命中数与迟到数、各层占用、两个 KV 池的余量、每步耗时。

用途：调参与复核的唯一依据。任何性能结论都必须能追溯到这些观测。

## 8. 核显后端（专家分担）

核显只在这条缝上参与：未命中专家的算力分担。视觉编码器、表行聚集与加权聚合、图像与视频预处理是各自独立的管线，不经过本接口（见 engine §13）。

### 8.1 作业与工人

两个类型：

| 类型 | 内容 |
|------|------|
| `ExpertJob` | 一层的一批未命中专家：层号、该层三矩阵的档与块几何、专家 id 列表、已按档量化的激活、输出缓冲 |
| `ExpertWorker` | `available()`、`submit(job)`、`wait()`。一个实现是 CPU 线程池，一个实现是核显 |

调用方是步循环：把一层的一批未命中专家交出去，在**同一步的汇合点**调用 `wait()` 取回结果。这里不引入设备概念——worker 的语义是「算这批专家的人」，CPU 与核显同形，分派按算力强度与带宽强度（[proposals.md](proposals.md) 的 P-04）。

粒度取一层一批：每步至多 48 次提交，队列开销可忽略；不再切细，因为每步只有一个汇合点。

### 8.2 两套资源，两个限制点

| 资源 | 谁在争 | 限制点 | 依据 |
|------|--------|--------|------|
| PCIe 字节 | 权重换入显存、KV 换入、本步必需表行 | 第 3 节的字节预算仲裁器 | 过 PCIe 的搬运 |
| DDR 总线 | CPU 与核显 | 独立的总线份额限流器 | 核显与 CPU 共享内存总线 |

两者不合并：专家在 CPU 就地计算走的是 DDR 而不是 PCIe，把它的字节记进 PCIe 预算会算错账。

总线份额的取值来自机器画像（第 6 节）的一个新字段：一个 decode 步里允许核显占用的总线字节数。默认 0，即不使用核显。份额上限必须实测（[risks.md](risks.md) 的 R-08）；环境2 的带宽型争用实测见 engine §13。

### 8.3 同步与归约

- 每步仍只有一个显存与主机的汇合点；核显的 `wait()` 由步循环在该汇合点内调用，worker 不得自行引入第二个同步点。
- 结果按专家 id 全序并入，与 [ADR-009](adr/ADR-009-correctness-acceptance-criteria.md) 与 engine §16 的归约顺序要求一致。
- 归约顺序固定之后，同配置下的可复现性按 8.5 的两档口径界定。

### 8.4 降级与失败

| 情形 | 处理 |
|------|------|
| 无运行时、无可用设备、设备节点打不开 | 初始化阶段 `available()` 返回假，退回纯 CPU 路径，不算错误 |
| 运行中失败（含驱动复位） | 该 job 重派给 CPU 并计入观测；当前步不中断 |
| 份额为 0 | 不向核显提交任何 job，等价于未启用 |

R-08 记录的同类平台先例伴随 GPU 复位，故失败路径必须是可退化而不是崩溃。

### 8.5 正确性口径

- 份额为 0（不启用核显）时，逐位口径不变。
- 启用核显后只要求分布级一致：同一输入下核显路径与 CPU 路径的输出差异须落在 ADR-009 定的容差内。逐位不成立，因为两边的整数累加顺序不同。
- 因此「启用核显」这一开关不得进入任何逐位复现的验收配置。

### 8.6 本仓库的落法

接口、纯 CPU 的 worker、核显占位实现（初始化即报不可用并附探测结论）、总线份额限流器进 `src/experts` 与 `src/scheduling`。核显内核要等 SPIR-V 工具链到位，现状见 engine §13 的实测。接口不绑定图形 API；第一套实现取 Vulkan compute，因为环境2 上它的运行时依赖为零新增。

已落地的是接口这一层：`src/experts/expert_worker`（`ExpertJob`、`ExpertWorker`、`CpuExpertWorker`、核显占位 `IgpuExpertWorker`，以及 8.4 那条重派语义 `run_job_with_fallback`）与 `src/scheduling/bus_share`（份额默认 0 即关闭）。核显内核本身仍待工具链，故占位实现的 `available()` 恒假、失败原因里带上本节引用的探测结论。
