# 测试环境硬件配置

本文档记录两套测试环境的硬件规格。两套都是实体机器：环境1 是本机（Windows 11 宿主 + WSL2），环境2 是另一台原生 Ubuntu 机器。规格来源为 Intel / NVIDIA 官方 ARK 及厂商规格页 [S-31]，核实时间 2026-10。研究结论与引擎设计见 [README.md](README.md)（文档索引）。

| — 频率 | P 基频 3.9 / 睿频 5.4（TVB 5.5 GHz）；E 基频 3.3 / 睿频 4.6 GHz |

使用方式说明：环境1 的实体机为本机，日常在 Windows 宿主之上的 WSL2 虚拟机内运行（`.wslconfig` 将虚拟机内存上限设为 16GB，实测可见 15.6 GiB；GPU 经 `/dev/dxg` 直通）。因此环境1 的内存容量与 PCIe 有效带宽有两套口径——WSL 内与 Windows 宿主，引用时必须写明测在哪一侧。2026-10-09 实测内存带宽在两套口径下基本相同，差别在容量（见下方实测值）。环境2 是原生 Linux，无此分歧。

## 实测值（环境2）

原始记录由同一组脚本产出（该机为原生 Linux，运行时需显式传 `--env 环境2`）。驱动 595.99.02、CUDA 13.2。

| 项目 | 实测 | 规格值 | 日期 |
|------|------|--------|------|
| 内存带宽 copy | 64.4 GB/s（引擎未运行）；引擎常驻时为 60.8 | 无厂商值 | 2026-10-09 |
| 内存带宽 triad | 53.7 GB/s（引擎未运行）；引擎常驻时为 42.9 | 理论峰值 70.4 GB/s | 2026-10-09 |
| 内存容量可见值 | 61.0 GiB | 64GB 标称 | 2026-10-09 |
| PCIe 链路宽度 | 当前 x8（两卡同值，采样期间未变） | 该型号电气为 x8 [S-32] | 2026-10-09 |
| PCIe 链路代数 | 空闲 gen1，持续负载下 gen5（21 次采样两卡配对观测） | gen5 x8 | 2026-10-09 |
| PCIe 有效带宽 H2D | GPU0 28.64 / GPU1 19.81 GB/s（256 MiB 档，引擎未运行） | 名义 31.5 GB/s | 2026-10-09 |
| PCIe 有效带宽 D2H | GPU0 19.96 / GPU1 14.42 GB/s（同上） | 名义 31.5 GB/s | 2026-10-09 |

读数：

1. 内存带宽实测为环境1 的一半左右：triad 42.9 对 87.2 GB/s（比值 2.03），copy 60.8 对 110.1 GB/s（比值 1.81）。厂商规格比值是 1.91，实测落在两个算子之间——原先只是规格推断的「环境1 内存带宽约为环境2 的 1.9 倍」现在有实测支撑。
2. 两套环境各只跑到自身理论峰值的约 65% 与 61%，效率接近，说明两侧口径可比。
3. 链路代数会随负载变化：空闲读到 gen1、持续负载下升到 gen5（同一次测量中两卡配对采样 21 轮，负载中的卡为 gen5、空闲卡为 gen1）。因此引用档位必须写明是否处于持续负载；空闲值反映省电状态，不代表链路能力。
4. 有效带宽（仅测到 16 MiB 档，因引擎常驻后每卡仅剩 53 至 106 MiB 显存）：H2D 28.37、D2H 19.11 GB/s。D2H 比 H2D 低约 33%，与环境1 上「D2H 略高于 H2D」方向相反——两平台方向性不对称，原因待查（怀疑与该机 IOMMU 有关）。大块档位（64/256 MiB）需在引擎停机的窗口内补测，届时才能给出饱和值。
5. 第二卡（GPU1）本次无法测量：其可用显存仅 53 MiB，所有档位被跳过。`G-08`（第二卡 PCIe 带宽，门禁）因此仍待停机窗口补测。
4. 有效带宽（引擎停机后测，256 MiB 档已饱和）：两卡不对称 —— H2D GPU0 28.64 对 GPU1 19.81 GB/s（69%），D2H GPU0 19.96 对 GPU1 14.42 GB/s（72%）。两卡的链路能力（`max_link_width` 8、32 GT/s）、根端口（分别为 CPU 的 `00:06.0` 与 `00:06.3`，中间无交换机）、测试期间的状态与时钟（均 P1、约 2850 MHz SM、13.8 GHz 显存）、AER 可纠正错误计数（两卡全 0）完全一致，因此该差异未被解释，需换槽复测或做电学层诊断才能定性。
5. 有效带宽的两个方向在所有测量中都D2H 低于 H2D（环境2 两卡比值约 0.70–0.73），而环境1 上方向相反（D2H 略高于 H2D）。方向性不对称是环境2 平台的属性，与环境引擎是否运行无关；怀疑与该机 IOMMU 有关，未验证。
6. 内存带宽受引擎常驻影响明显：引擎未运行时 triad 53.7 GB/s，常驻时降到 42.9（约 −20%）。因此跨环境比较内存带宽时，两侧必须同为「引擎未运行」。
7. 两套环境的驱动与 CUDA 版本不同（环境1 为 617.14 / CUDA 13.3，环境2 为 595.99.02 / CUDA 13.2），引用数值时必须连同版本一起标注。

## 实测值（环境1）

原始记录在 `measure/results/`，运行方式见 [../CONTRIBUTING.md](../CONTRIBUTING.md) 第 7 节。

| 项目 | Windows 宿主 | WSL2 虚拟机 | 规格值 | 日期 |
|------|-------------|------------|--------|------|
| 内存带宽 copy | 110.1 GB/s | 114.5 GB/s | 无厂商值 | 2026-10-09 |
| 内存带宽 triad | 87.2 GB/s | 85.9 GB/s | 理论峰值 134.4 GB/s | 2026-10-09 |
| 内存容量可见值 | 47.4 GiB | 15.6 GiB | 48GB 标称 | 2026-10-09 |
| PCIe 链路宽度 | 当前 x8 | 同宿主（读同一驱动） | 该型号电气为 x8 [S-32] | 2026-10-09 |
| PCIe 有效带宽 H2D | 未测 | 26.61 GB/s（256 MiB 块） | 名义 31.5 GB/s | 2026-10-09 |
| PCIe 有效带宽 D2H | 未测 | 28.37 GB/s（256 MiB 块） | 名义 31.5 GB/s | 2026-10-09 |

读数：

1. 内存带宽在两套口径下基本相同，差别在容量——WSL 的虚拟机内存上限把可见容量压到 15.6 GiB。因此「WSL 内测不准宿主内存带宽」这一预期被实测否定。
2. 实测带宽低于规格上限属正常，厂商值是无负载上限；87.2 GB/s 的 triad 是 134.4 GB/s 理论峰值的 65%。
3. PCIe 实测 `width.current = 8` 与厂商规格一致，不是降档：`nvidia-smi` 的 `width.max = 16` 报的是槽位或接口能力，不能当作显卡能力。
4. PCIe 有效带宽实测（WSL 口径，pinned 内存与大块显存互拷）：256 MiB 大块 H2D 26.61、D2H 28.37 GB/s，为名义 31.5 GB/s 的 84% 与 90%，属协议开销下的正常水平——这反过来确认链路确实跑在 gen5 x8。
5. 小块搬运的代价远高于按字节折算：1 MiB 块的 H2D 只有 13.56 GB/s，不到 256 MiB 块的一半，属延迟受限。这是设计里「减少 IO 次数优先于减少字节数」（[design/engine.md](design/engine.md) 附录 A 第 11 条）与「批量聚合」的实测依据。
