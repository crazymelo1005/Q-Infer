# ADR-009：正确性验收口径——逐位只在固定开关下要求，默认真实配置用分布级

状态：Accepted
日期：2026-10-10

---

## 背景

[engine.md](../engine.md) §17 序 2 的验收写的是「同档困惑度须与参考实现一致」。G-14 实测（环境2，2026-10-09）表明这条按字面无法执行：

1. 参考引擎跨运行不逐位一致：同配置两次 fp16 生成的贪心序列在第 40 个 token 首次分歧；只有加上 `--adapt-every 0 --pcie-frac 0` 才逐位相同（512/512，见 [research/01](../../research/01-strata-engine.md) §4.1）。
2. 参考实现的困惑度取不到：原生（IQ）pack 下 `--dump-logits` 产出 0 字节文件（源码注释亦如此说明），没有可比对象。
3. 本设计的归约路径本身就与上游不同：结果由显存、CPU、核显三路累加归并（[engine.md](../engine.md) §16），要求默认真实配置逐位一致，等于把设计逼回上游的归约顺序。

## 决策

1. 逐位判据只在固定开关组合下要求：对齐到「关掉自适应搬运 + 关掉跨设备专家计算」（参考引擎侧是 `--adapt-every 0 --pcie-frac 0`；本设计侧对应「关掉自适应换入」与「未命中专家不跨设备」两个开关）。该组合下，本设计与参考实现对同一提示、同一采样的贪心输出序列必须逐位一致。这是内核与算术层面的回归判据。
2. 默认真实配置下不要求逐位，改用分布级判据：同一提示、同一采样的贪心序列的「首次分歧位置 + 一致率」（工具 `measure/kv_quality.py`），以及任务级指标。
3. 困惑度不作为序 2 的门槛。在自家 logits 通路建成前，困惑度类阈值保持未定，且不得引用参考引擎的困惑度——取不到。替代口径是同批真实文本上的逐位置 NLL 分布（需要自家 logits），或任务级 pass@1。
4. §17 序 2 的验收据此改写为：① 固定开关下与参考实现的贪心序列逐位一致；② 默认配置下自身的可重复性——同一提示两次运行的一致率（用 `kv_quality.py` 的对照 run 口径）须为 100%；若某处归约顺序确实不可固定，须在 §16 的白名单里显式声明，并改用分布级判定。

## 备选方案

1. 坚持「困惑度与参考实现一致」。否决：没有可比对象（取不到参考 logits）。
2. 只在默认配置下要求逐位。否决：参考引擎自己都做不到，且会限制本设计的三路归约。
3. 干脆放弃逐位判据，只做任务级。否决：内核与算术层面的回归会失去最灵敏的探针——固定开关下的逐位比较能在毫秒级发现一个错的舍入。

## 后果

正面：

- 判据可执行：固定开关口径下有一套现成工具与已记录的 oracle（参考引擎的贪心序列）。
- 内核回归与产品级验收分开，各自的灵敏度对得上各自要抓的问题。

负面：

- 固定开关口径的覆盖有限（它关掉了自适应与跨设备计算，而这两处正是设计改动最大的地方）；默认真实配置只能靠分布级判据，灵敏度较低。
- 困惑度类阈值在自家 logits 通路建成前一直是空的，质量闸门不完整。
