# ADR-010：路由的读法——按张力声明的档读，bf16 那条契约只属于引擎那份 pack

状态：Accepted
日期：2026-10-11

---

## 背景

MTP 草稿层的路由张力（`ffn_gate_inp.weight` / 引擎那份叫 `mlp.gate.weight`）在本地两份 pack 里档不同：

- 主模型部署那份（`sc117-iq2_xxs` 与 IQ2 档）：BF16；
- 社区那份 MTP pack（`mtp-Qwen3.8-Flash-Next-Q8_0.gguf`）：F32（5242880 B = 2560×512×4，环境2 直读）。

而 [S-44] 记的引擎路由契约是「bf16 投影 + 激活也按 bf16 舍入」，引擎自注「此处若改用 fp16 激活会引入 8.100e-03 的误差并翻掉选择」。两种读法算出的 logits 不同，top-10 的成员或顺序因此可能不同 —— 而 top-10 一变，投机草稿的接受率就跟着变（[S-62] 的 0.89/0.86/0.85 是在引擎那份 pack 上测的）。

这不是新的歧义：本仓库已有多处「同一逻辑角色、逐文件档不同」的事实——`hc_*_norm.weight` 是 F32 而三个投影是 BF16（[S-53]）、`output.weight` 与 `token_embd` 是 IQ4_XS（[S-54] 更正）、专家 gate/up 逐层换档（[S-36]）。路由只是又一处。

## 决策

1. **逐张力读它自己声明的档**：F32 的路由按 F32×F32 算；BF16 的路由按 BF16 算（权重与激活都舍入到 bf16，保留 [S-44] 那条契约）。
2. [S-44] 那条「激活也按 bf16 舍入」明确为引擎那份 pack 的约定，不是全局契约。它成立的前提是那份 pack 的路由声明为 BF16；对声明为 F32 的路由，正确的读法是 F32×F32，而不是「把 F32 也舍成 bf16 走同一条路」。
3. 判据仍然照 [ADR-009](ADR-009-correctness-acceptance-criteria.md)：不做跨档的逐位要求；同一份 pack、同一配置下可复现即可。

## 后果

1. 同一模型在两份 pack 上给出的投机接受率可能不同，引用时必须写明是哪一份 pack 上测的——与 [S-36] 那条「分派映射是逐文件的数据」是同一类要求。
2. 本仓库的读路径按此实现：路由的精度随张力声明走（`moe_layer` 不再硬要求 BF16），与 `GrTensor`/`GrPrecision`（门控残差逐张力声明精度）、`MatrixSpec.format`（按档分派内核）三条口径一致。
3. 若日后要求「两份 pack 给出同一个接受率」，那是一条新的、更强的口径（需要把 F32 也舍成 bf16 以对齐引擎那条路），得单列并写清它对草稿质量的影响——不在本 ADR 的范围。

## 依据

[S-44]（引擎路由契约与那句 8.100e-03 自注）、[S-53]（门控残差逐张力精度）、[S-62] 与 [research/02](../../research/02-qwen3.8-flash-next.md) §9（两份 MTP pack 的逐张力对照与那份路由 F32 的实测）。
